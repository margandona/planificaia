# AGENTS.md

PlanificaIA — ethical AI lesson-planning generator for the Chilean curriculum (Mineduc). Firebase backend + static Vue 3 SPA, no build step. pnpm 11.18.0, Node >= 22. All commits/docs/UI strings in Spanish (es-CL); code identifiers in English.

## Commands

- Install: `pnpm install` (workspace: root + `functions` + `scripts`)
- **Unit tests (what CI runs):** `pnpm --dir functions test:unit`
- Frontend E2E (against PRODUCTION, public pages only): `python public/js/frontend.test.py` (needs `pip install playwright` + `python -m playwright install chromium`)
- Dependency audit: `pnpm audit --prod --audit-level=high` (root and `functions/`)
- No linter, typecheck, or build step. Syntax-check edited JS with `node --check functions/index.js` / `node --check functions/index.test.js` / `node --check functions/logic.js` / `node --check public/js/core.js` / `node --check public/js/app.js` / `node --check public/js/pages/<page>.js`
- Emulators: `firebase emulators:start` (requires Java on PATH; `integration.test.js` auto-skips when the emulator is down)

## Critical gotchas

- **Pure logic lives in `functions/logic.js` (U0/B12)** — a module with NO firebase imports (no `initializeApp()`). `functions/index.js` imports its pure symbols from `./logic.js` and re-exports `TERMS_VERSION`, `PRIVACY_VERSION`, `RETENTION_POLICY`, `retentionCutoffIso`, `validateTermsAcceptance`; `functions/index.test.js` and `scripts/eval-batch.mjs` import the pure logic from `./logic.js` instead of mirroring it. When you change pure logic (rules, schema, quality, coherence, planning record, whitelists, plans), edit `logic.js` — index.js consumes it, so tests stay honest. Run `node --check functions/logic.js` after edits.
- **`TERMS_VERSION`/`PRIVACY_VERSION` live in FOUR places (S-6/RF-013)** — `functions/logic.js` (source of truth, re-exported from `index.js`), `functions/index.test.js` (imported from `logic.js`), `functions/index.js` (re-export) and `public/js/core.js` (re-exported to `app.js`). Bumping a version (a legal/policy change) must update `logic.js` AND `public/js/core.js`; `acceptTerms` rejects stale versions server-side, and `hasAcceptedTerms()`/the consent modal enforce re-acceptance client-side. Frontend E2E (`frontend.test.py`) includes an axe-core WCAG 2.2 AA scan of the 7 public routes — keep them violation-free.
- **No `functions.config()`** — API keys come only from `process.env` via `functions/.env`, which the deploy workflow (`deploy.yml`) writes from GitHub secrets (`DEEPSEEK_API_KEY`, `GEMINI_API_KEY`, `GEMINI_FALLBACK_ENABLED`). Never commit `.env` files.
- **Deploy happens on push to `main`** via `.github/workflows/deploy.yml` (hosting + functions, `--only hosting,functions`). It only triggers on `functions/**`, `public/**`, firebase config, and rules files — **docs-only commits skip deploy**. Reglas/índices de Firestore **no se despliegan por CI**: la SA (`GCP_SA_KEY`) no tiene el rol `Firebase Rules Admin` (el test de compilación devuelve 403). Publicar reglas/índices a mano con `npx firebase-tools deploy --only firestore` (con credenciales con rol) o conceder el rol a la SA. CI (`ci.yml`: unit tests + audit + E2E) runs on every push/PR.
- **`gh` CLI is not authenticated.** To poll Actions via the GitHub API, recover the token with `"protocol=https`nhost=github.com`n`n" | git credential fill` (take the `password=` line) and use it as `Authorization: token <tok>` against `https://api.github.com/repos/margandona/planificaia/actions/runs`.
- **Seed/data scripts hit PRODUCTION Firestore directly** (no emulator). They need admin credentials: set `GOOGLE_APPLICATION_CREDENTIALS=<path>` (most scripts) or `FIREBASE_SA_PATH` (`seed-prompt-templates.mjs`, `seed-feature-flags.mjs`, `seed-test-users.mjs`, `seed-methodology-catalog.mjs`, `seed-external-tool-profiles.mjs`). The gitignored SA file `planificacion-con-ia-firebase-adminsdk-fbsvc-77c69d86f8.json` exists in the repo root. Scripts with deterministic doc IDs are idempotent; dry-run flags exist on some (`seed-epja.mjs --dry-run`). **`seed-test-users.mjs` crea/actualiza cuentas de prueba (admin.prueba / docente.prueba / piloto.prueba, contraseña `PlanIFia-2026`, claims+perfil con términos aceptados) — credenciales documentadas en `MANUAL_PRUEBAS.md`.** Los tests E2E (`frontend.test.py`) corren contra producción (públicas, axe WCAG 2.2 AA, 13 tests).
- **Admin access = custom claim `admin == true`** (`firestore.rules`); el frontend también trata `role === 'admin'` como admin (`isAdmin()` en `core.js`, `store.claims`). `prompt-templates`, `catalog`, `curriculum`, `config/feature-flags` writes and `audit-logs`/`ai-costs`/`feedback` reads are admin-only; `plannings` are owner-only. Client and admin SDKs both go to the same production project — no separate test env.
- **Feature flags (U17/U17b, DEPL-01): despliegue gradual** — defaults en `FEATURE_FLAGS` (`functions/logic.js`, todas `false`). Documento `config/feature-flags` (admin-write, read público): por flag un booleano global (`false` = kill-switch para TODOS incluso allowlist) + `rollout: { flag: 0-100 }` (porcentaje por bucket determinista `userFlagBucket(uid)` `%100`) + `allowlist: { flag: [uid,...] }` (pilotos siempre ON mientras la flag global sea `true`). **El admin SIEMPRE ve todo activado** (`resolveUserFeatureFlags(source, uid, isAdmin)`); el panel "Funcionalidades" de `institucional.js` (solo admin) administra los flags vía `updateFeatureFlags` (auditoría `update-feature-flags`). Caché 5 min en backend (`getFeatureFlags`) y frontend (`loadFeatureFlags`); al cambiar un flag se `clearFeatureFlagsCache()`. **El `Layout` solo lee flags con sesión iniciada** (watch sobre `store.user`) — las rutas públicas NO abren Firestore (requisito para que el E2E `networkidle` se asiente). Seed idempotente: `scripts/seed-feature-flags.mjs` (`--flag`, `--rollout=flag=25`, `--allow=flag=uid1,uid2`; sintaxis `--clave=...`, no con espacio). Funcionalidades gateadas: `methodologyRecommendationsEnabled`, `gamificationModuleEnabled` (menú "Gamificaciones" + `#/gamificaciones` + portal participante), `externalPromptGeneratorEnabled` (menú "Prompts externos"), `tpContextEnabled`, `localContextEnabled`.

## Architecture

- **`functions/index.js` (~2574 lines after U0/B12; pure logic extracted to `logic.js`)** — all Cloud Functions: `generatePlanning`, `regenerateSection`, `approvePlanning`, `submitFeedback`, `exportPlanning`, `acceptTerms` (S-6: aceptación versionada RF-013), `setUserPlan` (S-7: planes freemium `PLANS` = free 10/día, pro 1000/día; admin-only, escribe `plan` en `users/{uid}` y en `organizations/{org}/members/{uid}`), `setUserRole`, `createOrganization`, `inviteMember`, `acceptInvite`, `removeMember`, `updateFeatureFlags` (U17b: admin-only, valida con `normalizeFlagUpdate`, escribe `config/feature-flags`, invalida caché, auditoría `update-feature-flags`), `runRetentionSweep` (S-6: purga oportunista de retención 29.3 — ai-costs 2 años, logs 1 año; se llama desde generate/regenerate; un Cloud Scheduler no es desplegable por IAM), `onNewAuditLog` (v2 onCall/onDocumentCreated). AI: DeepSeek primary (`deepseek-v4-flash`), Gemini fallback (`gemini-2.5-flash`). Límite diario atómico (U0/B3) vía `reserveDailyAllowance`/`releaseDailyAllowance` sobre `usage/{userId}__{YYYY-MM-DD}`; `regenerateSection` registra `ai-costs` + `budget-usage` (U0/B4) y la whitelist `ALLOWED_REGENERABLE`/`isRegenerableSection` (U0/B1); `runCoherenceReview` registra costos (U0/B5). Planning types: `class | unit | monthly | annual | evaluation | multigrade` — central `PLANNING_TYPES` const (per-type OA limits); type-aware `validateOutputStructure`, `normalizePlanningOutput`, `buildPlanningRecord`, `buildTypeInstruction` (per-type JSON schemas + "REGLAS OBLIGATORIAS" en unit/monthly/annual/multigrade: evaluación con criteria+feedbackStrategy y duraciones coherentes), `buildMethodologyDistribution` (distribuye las metodologías seleccionadas por clase/semana).
- **Frontend S-5.4 (módulos ES, sin build step):** `public/js/core.js` (~424 lines) exporta toda la infraestructura compartida (firebase, store, helpers, UI, Layout, `PLANS`, `setUserPlanFn`, `TERMS_VERSION`/`PRIVACY_VERSION`) + re-exports de `vue`/`firebase/*`; `public/js/app.js` (~559 lines) es la entrada (páginas ligeras Landing/Login/Register/VerifyEmail/Dashboard/Profile + router con `import()` dinámico); las páginas pesadas viven en `public/js/pages/`: `wizard.js` (~507) asistente de 10 pasos (paso 4 multi-select de metodologías ≤4 en unit/monthly/annual, paso 6 `<select>` de evaluación con `value: data.evaluationType` + `onChange`, paso 7 DUA rápido con `DUA_SUGGESTED`/`setDuaSelection`/`duaTotal`), `detail.js` (~394, incluye regeneración por sección U0/B8 con `regenSection`/`startRegen`/`acceptDraft`/`rejectDraft` y la card "Calidad y coherencia" U0/B9), `institucional.js` (~367, panel colegio + "Planes del equipo" que asigna Free/Pro por miembro + card "Funcionalidades" de feature flags solo-admin), `editor.js` (~576), `gamificaciones.js` (~386, editor de experiencias + publicar/revisar evidencias), `externos.js` (~151, generador de prompts a herramientas externas), `participar.js` (~110, portal del participante seudónimo en `#/participar/{codigo}`); todas importan de `../core.js`. Si añades un símbolo compartido, expórtalo desde `core.js` y recuerda que los módulos de páginas importan por nombre.
- `scripts/` — curriculum ingestion and seeding: `ingesta-curriculo.js`, `scrape-curriculum.mjs`, `seed-epja.mjs`, `seed-catalog.mjs` (v5: incluye `country: 'cl'`/`countryName` — base multi-país S-7), `seed-templates.mjs`, `seed-prompt-templates.mjs`, `seed-methodology-catalog.mjs`, `seed-feature-flags.mjs` (U17: doc `config/feature-flags`, `--flag`/`--rollout=flag=25`/`--allow=flag=uid`), `seed-test-users.mjs` (cuentas de prueba), `seed-external-tool-profiles.mjs`, `pilot-metrics.mjs` (métricas de adopción por módulo, sección 7), plus `verify-*`/`debug-*` helpers. Curriculum lives in `curriculum/<subject>/<level>/...`; catalog in `catalog/subjects`; prompt templates in `prompt-templates` (each with `types` array + cascade selection subject+type → type → subject → generic).
- Firestore collections: `curriculum` (public read), `catalog` (public read), `prompt-templates` (admin), `config/feature-flags` (admin-write, public read), `methodology-catalog` (public read), `tp-specialties` (public read), `plannings` + `plannings/{id}/versions` (owner), `users` (owner), `gamified-experiences` (+ versions/missions/rules, owner/org), `badges` (public read), `external-prompts` (owner), `external-tool-profiles` (public read), `ai-costs`/`audit-logs`/`feedback` (function-write only).
- Docs: `PLAN_ACTUALIZACION_GAMIFICACION.md` (fases U0–U17b + DEPL-01, cada cierre con nota **Cierre (fecha):**), `MANUAL_PRUEBAS.md`/`.pdf` (cuentas de prueba + pasos de QA/aceptación), `MANUAL_USUARIO.md`/`.pdf` (end-user manual), `MODELO_NEGOCIO.md`, `RESUMEN_EJECUTIVO.md`.

## Conventions

- Commit messages: Spanish, phase-prefixed — `s2: ...`, `docs: ...`, `ci: ...`, `s1: ...` (see `git log`).
